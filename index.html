01 / PRINCIPLE

The system does not ask, “did the software say PASS?”

It asks whether the claim survived identity, persistence, replay, review, and contradiction.

A valid signature is not truth. A hash match is not trust. A quorum count is not protocol finality. The evidence boundary is part of the result.

    ENGINE CORE

    Protocol-independent event semantics

    Integrations can change the subject under review without changing the assurance event protocol. RChain is the first serious external adversarial workload, not the definition of the engine.

    typed ESMCLIzero runtime npm depsversioned verifier registry
    VERDICTS

    PASS / BLOCKED / FAIL

    No single boolean pretending every failure means the same thing. Incomplete evidence can block a claim without falsely proving its negation.

    NEGATIVE CONTROL

    Valid signature. Wrong operation.

    Cryptographic validity alone does not grant semantic authority. Operation identity is bound and checked.

    PERSISTENCE

    Recovery is part of correctness.

    WAL-backed journals and independently persisted process state make restart behavior inspectable instead of incidental.

    TRUST

    The package cannot choose its judge.

    Untrusted evidence cannot select reviewer policy, claim, task, trust pins, or verifier code.
